# DocuRAG

A document knowledge base API built with FastAPI.

## Project Overview

DocuRAG is a backend learning project designed to support document ingestion, text processing, vector retrieval, and source-grounded question answering.

The project is being developed incrementally, with a focus on API design, automated testing, configuration management, and reproducible development environments.

## Current Features

- FastAPI application initialization
- Health check endpoint (`GET /health`)
- Automatically generated Swagger UI documentation (`/docs`)
- Environment-based configuration using Pydantic Settings
- Basic API tests using pytest

## Planned Features

The following features are not yet implemented:

- PDF and TXT document uploads
- Document parsing and text chunking
- Text embeddings and vector similarity search
- PostgreSQL and pgvector integration
- Redis caching
- Source-grounded question answering
- Docker Compose deployment
- Retrieval evaluation with different chunk sizes and Top-K settings

## Requirements

- Python 3.11
- Git
- Linux or WSL Ubuntu

## Local Setup

Clone the repository or navigate to the project directory.

Create a virtual environment:

```bash
python3.11 -m venv .venv
source .venv/bin/activate
```

Install dependencies:

```bash
python -m pip install -r requirements.txt
```

Create the local configuration file:

```bash
cp .env.example .env
```

Start the API:

```bash
python -m uvicorn app.main:app --reload
```

## Document API

The current document API supports in-memory CRUD operations for document metadata.

### Create a Document

**Request**

```http
POST /documents
Content-Type: application/json
```

```json
{
  "title": "FastAPI Guide",
  "filename": "fastapi.pdf"
}
```

**Example Response — 201 Created**

```json
{
  "id": 1,
  "title": "FastAPI Guide",
  "filename": "fastapi.pdf",
  "created_at": "2026-10-08T08:00:00Z"
}
```

The timestamp above is illustrative. Actual timestamps are generated by the server.

### Available Operations

| Method | Endpoint | Description |
|---|---|---|
| POST | `/documents` | Create document metadata |
| GET | `/documents` | List documents |
| GET | `/documents/{document_id}` | Retrieve a document |
| DELETE | `/documents/{document_id}` | Delete a document |

### Error Handling

- `422`: Invalid request data or unsupported fields
- `404`: Document does not exist
- `204`: Document deleted successfully

### Current Limitations

- All document records are held in process memory.
- Records are lost when the application restarts.
- File upload and PDF parsing are not implemented yet.
- Database persistence will be introduced in a later development stage.

## Security Notes

- Local secrets are stored in `.env`.
- `.env` is excluded from Git.
- `.env.example` contains only non-sensitive example configuration.
- Virtual environments and local document storage directories are excluded from version control.
